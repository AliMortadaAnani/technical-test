1- Problem Definition : what is the problem we are trying to solve?

AliMA Corporation (a hypothetical company for the technical test)
is a startup that sells some products and services in some business domain...

Good news! AliMA is expanding!
Unfortunately, the AliMA team is facing a problem managing candidates' resumes and information gathered from the job applications
they are posting.
For example, the recruiting team has many applicants' CVs from WhatsApp chats, LinkedIn DMs, their email inbox...
And since AliMA is a professional company, they want to manage this task properly, guaranteeing to review each application
and totally avoid ghosting candidates they had contacted (shortlisted candidates)

For that reason, the AliMA CEO reached me (ALi Mortada Anani - fullstack developer) to create a solution for this problem
which is basically an internal dashboard web application that manages candidates applying for jobs at AliMA Corporation.

9- High level and Low level design : specify the user/system interactions
		===> here we set the ERD, database schema, dtos, endpoints of the api,...(very open to change)
		
the user opens the web application,
at login, he is required to enter username and password (hardcoded since it's a mock	auth)
dto for the frontend app (username,password)
system responds by allowing the user to navigate to the dashboard page (no real authResponse from api here since it's mock too)
same applies for logout

now for the real api (frontend backend communication)
user will have mainly 3 interactions with the api 
for creating a jobApplication record, user enters:
applicant name,applicant email,job title (system generates the id(auto incremental)
										,and dateOfCreation as now,and applicationStatus as new)

for updating , user selects the record from the list of applications and updates status
from new to inProgress or from inProgress to Done (api requires the id only for the update,since status will be auto derived)


the dashboard page also shows a table of the list of registered jobApplications:
the table shows these record info:
id,name,email,job title,date of creation,status

Note:
in our context:
new is any applicant record that has been shortlisted by AliMA Corporation (no contact from the company yet),
the user enters manually each application he tends to follow up with

inProgress is any applicant record that has been contacted by the HR team so the company must follow the process with
this candidate

Done is any applicant record that has ended this process whether he was hired,or been rejected

so in other words,
new jobApplications are the total candidates that applied and were shortlisted by HR side (no contact yet)
inProgress jobApplications are the total shortlisted candidates that have been contacted by HR
Done jobApplications are the total candidates that have been hired or rejected after being contacted by HR
